# User Story Template

## Story

**ID:** US-___
**Title:**

> As a [role],
> I want [capability],
> So that [business outcome].

## Context

Why this story exists — the business problem or BRD requirement it traces to.
Link the BRD ID and RTM row.

## Acceptance criteria

Write every criterion in Given / When / Then form, and make each one testable.
A criterion a tester cannot execute is a wish, not a requirement.

- [ ] **AC1:** Given [precondition], when [action], then [observable result].
- [ ] **AC2:** Given [precondition], when [action], then [observable result].

## Edge cases and exceptions

- What happens on invalid input?
- What happens when a dependency is unavailable?
- What is explicitly NOT covered by this story?

## Dependencies

- Data, systems, other stories, or decisions this story waits on.

## Out of scope

What this story deliberately does not do (prevents scope creep in review).

## Definition of done

- [ ] Acceptance criteria reviewed with stakeholders
- [ ] Traced in the RTM
- [ ] UAT script written from the acceptance criteria
- [ ] Tested and signed off by the business owner
